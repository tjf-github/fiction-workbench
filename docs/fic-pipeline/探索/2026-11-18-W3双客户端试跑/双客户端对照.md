# W3 推门场 · Cherry Studio 与 OpenFic

同一份 `w3.md`，两边各完成初稿、Grok 句级审计和筛审后返修。两份纯文本按《真实1.txt》排版，正文沿用模型输出。

| 客户端 | 写作模型与技能读取 | 字数变化（不计空白，含标点） | 样例 |
|---|---|---:|---|
| Cherry Studio 的「写作」智能体 | 界面显示 DeepSeek V4.1 Flash／深度求索。初稿与返修均显示成功读取 88 行的 `SKILL.md`，安装副本与 v2 附件 SHA-256 相同 | 1145 → 1093 | [真实-Cherry-Studio.txt](真实-Cherry-Studio.txt) |
| OpenFic v0.12.0 的 Build agent | 通过原生会话 API 使用模型 `deepseek-v4-flash`。两次 `activate_skill` 返回内容均与 v2 正文核对一致 | 886 → 844 | [真实-OpenFic.txt](真实-OpenFic.txt) |

两份审计均经 Claude Code 调用 CC Switch，网关记录实际模型 `grok-4.7`，读到 v2 原文。Cherry Studio 初稿启用低推理、返修选关闭。OpenFic 初稿请求 low、返修请求 off。两个客户端的 agent 指令、模型标签和上下文装配有差别。

## 读感与改稿

- **Cherry Studio 的权责摩擦更明显。** 嘉德丽雅压着便条，格尔曼要她查完还纸，嘉德丽雅回「不是今晚」。它把「白天补给时从岸上送来的」写进对白。Grok 指出了贝尔纳黛敲打过长、两处复读，以及结尾前把便条塞进口袋的问题。返修把纸压回桌上，也删了转驳人员的分账，但仍保留「它没往下压，也没替她指谁」这层代读，还添了一句评价贝尔纳黛说话分量的总结。
- **OpenFic 的敲打更轻。** 贝尔纳黛只问「今天岸上下来的人，你都认得清？」嘉德丽雅接下来就叫人。返修删掉了几处对称的叙述和解释，保留了她对贝尔纳黛的顾忌。它也把认出记号改写成「她自己站在舷边看人画在货牌上的」，多了一段上游没有的亲历。另有几处审计未点名的分段变动。
- **两边都没交代格尔曼认得落款借用的旧称呼。** OpenFic 稿提到落款是个嘉德丽雅不熟的旧称呼，她仍没有听见格尔曼解释自己认得它。OpenFic 也没把便条的到船时间明确写进正文。

Cherry Studio 筛审保留了嘉德丽雅听出旧日敲打的反应，修便条位置。OpenFic 采纳第 1–4 条，第 5 条涉及收尾，保留原结尾。两份 TXT 中的定位均来自 Grok，保留被筛掉的意见供对照。

OpenFic 使用隔离数据目录。导入的 v2 默认关闭，前两次尝试均未成功加载，启用后才开始计入本次对照。Cherry Studio 为本次试跑在「写作」智能体中导入并启用了 v2。样本只说明这个场面中两条流程实际写出了什么。
