# 针对中文小说句子的 skill 调研

2026-11-17。范围：寻找、阅读和筛选现有 skill，不安装、不执行外部仓库脚本、不调用模型改稿。检索使用 Exa，实际指令另从源仓库核对，研究副本及 SHA-256 见来源清单.json。共核读 7 个项目的主指令，并补读部分参考文件；未逐仓检查测试和提交历史。

## 当前要解决的问题

用户针对 Grok 两次试写指出的核心是句子本身不自然，尤其是书面措辞硬塞进对白、连续论证、莫名的技术细节。此前五条候选约束没有获得用户认可，不能记为有效经验。此次寻找逐句修改方法，不继续扩张情节规划。

## 候选

### 1. huoren-write：最贴近本次文本载体

[主指令](https://github.com/laoguo2025/huoren-write/blob/main/SKILL.md) · [人物声口](https://github.com/laoguo2025/huoren-write/blob/main/references/character-voice.md) · [痕迹库](https://github.com/laoguo2025/huoren-write/blob/main/references/ai-patterns.md)

专门处理小说与短剧的表达，不负责从零编剧情。对白检查覆盖听众、关系、说明性信息和过度周全的论证；这与本次问题直接相关。倾向先做删除和替换，同时限制新增事实。

局限：规则与示例并非完全一致。[示例](https://github.com/laoguo2025/huoren-write/blob/main/references/examples.md)中存在将原有心理内容改成另一种内容、删掉独立背景信息的处理；也有依靠沉默和小动作收尾的写法。不能把这些例文当作审美答案，更不能承诺它已适配 Grok。

### 2. story-skills / line-editing：最值得借用逐句编辑方法

[主指令](https://github.com/danjdewhurst/story-skills/blob/main/skills/line-editing/SKILL.md) · [逐句检查](https://github.com/danjdewhurst/story-skills/blob/main/skills/line-editing/references/line-edit-checklist.md) · [朗读检查](https://github.com/danjdewhurst/story-skills/blob/main/skills/line-editing/references/read-aloud-guide.md)

区分清晰、精确、简练、节奏及声音，要求具体修改理由和前后对照，承认作者的风格优先。朗读检查关注拗口、重复节奏和不像口头表达的对白；比单纯禁词更贴近本次需求。

局限：它属于较完整的小说项目工具链，涉及其他 skill、项目文件和 CLI；词级例子主要面向英语。这里只借用编辑问题和对照方式，不照搬英文词表或整套项目设施。默读模拟不冒充真实朗读验证。

### 3. chinese-grammar-proofreader：用于区分明确语病与审美不适

[主指令](https://github.com/orange4664/chinese-grammar-proofreader/blob/main/SKILL.md)

检查搭配、成分、语序、歧义、指代和句式混杂，区分明确错误、依赖语境和无明显语病，并主张最小修改。可用于排查基础问题。

局限：它明确排除泛润色，不能解决所有口吻与小说语感问题。小说口语省略也不能按考试句法机械纠正；仓库中的具体语法判断仍应独立核查。

### 4. Humanizer-zh：作为保守改句的参考

[主指令](https://github.com/op7418/humanizer-zh/blob/main/SKILL.md)

本次读到的修订版强调保留含义、限定和原有语域，逐项判断模板问题，允许概括和有功能的长短句、连接词。可以参考其减少误改的原则。

局限：主要服务文章、评论与文档，小说对白和人物声音的专项指导较少。它无法单独回答一句话是否像班森会说的。

## 不建议原样采用的项目

- [zh-novel-polish](https://github.com/chaserr/novel-craft/blob/main/skills/zh-novel-polish/SKILL.md)：确实针对小说句子，但对定语长度、“的”的数量及感悟结尾设硬配额，并鼓励动作感官扩写。判断：容易重复本轮因硬规则造成的新僵化。
- [novel-humanize](https://github.com/qi531416/novel-humanize/blob/main/SKILL.md)：把检测器表现作为目标，并规定标点清零和密度。判断：与用户当前的句子质量目标不一致。
- [human-writing](https://github.com/KKKKhazix/human-writing/blob/main/human-writing/SKILL.md)：通用范围大，主入口偏中文长帖，还包含全局标点禁令。[虚构参考](https://github.com/KKKKhazix/human-writing/blob/main/human-writing/references/fiction.md)对保留心理描写、区分场景和概述有帮助，但不宜整包覆盖诡秘小说的语体。

上述取舍基于指令内容和当前任务匹配度，不是经过模型对照得到的质量排名。

## 建议的最小下一步

先选 huoren-write 的对白检查，结合 line-editing 的逐句对照方式，审阅现有失败稿。每处只提交原句、问题性质、最小改法和原因，暂不重写全篇，也不要求补动作、维修知识或新的生活细节。

问题性质分别记为：明确语病、搭配或指代不清、书面与口语不合、对话中的信息负担、依赖上下文的审美判断。没有问题的句子保留；用户认为好读的改法才进入后续候选参考。先测试修改能力，再决定是否用于约束从零写作。

本轮没有验证任何 skill 对 Grok 4.7 的效果，也没有安装正式 skill。
