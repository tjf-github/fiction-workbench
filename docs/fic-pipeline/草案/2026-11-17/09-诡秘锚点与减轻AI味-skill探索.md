# 以《诡秘之主》为锚点，探索怎样形成减轻 AI 味的 skill

日期：2026-11-17，Asia/Shanghai。

范围：方法探索，供 agent-workflow 参考。用户明确只研究方法，暂不写样稿。本次未提取小说原文、未生成创作样稿、未进行模型对照、未创建或安装正式 skill。下述规则均为候选，不能作为效果结论。

## 核心判断

值得建设的是一套“从阅读判断中提取写作决策、通过对照检验、按失败修订”的方法。《诡秘之主》作为首个观察锚点，帮助把抽象的好坏落到具体文本；最终 skill 的效果取决于它能否改变成稿行为，并降低读者的修改负担。

“像《诡秘之主》”“少 AI 味”“小说写得好”分别评价，不能互相代替。术语和人名接近原作只能说明题材或设定接近；措辞朴素也可能仍然人物失真、因果薄弱。

## 一、先明确锚点究竟锚住什么

有三类材料，各有用途：

| 材料 | 要回答的问题 | 进入哪里 |
|---|---|---|
| 世界、人物与时间阶段事实 | 此时谁知道什么，能做什么，关系到了哪一步？ | 按书、按场景查阅的资料 |
| 原文的叙事处理及上下文 | 在这种场景里，信息、动作、对话和解释如何安排？ | 带适用条件的锚点参考 |
| 用户的阅读与改稿判断 | 哪些地方让用户出戏，什么修改才算改善？ | 候选规则与评价依据 |

资料正确是创作条件，不能单独证明文字自然。原文中的成功处理也不自动适合另一种场景。最终应形成“可迁移方法＋按书参考”，避免把某书的术语和句型固化为通用 skill。

## 二、先把“AI 味”变成可以讨论的阅读问题

以下是供用户校准的观察维度，尚未认定为用户偏好，也不是对《诡秘之主》文风的实证总结。

| 阅读症状 | 优先检查什么 | 不能机械采用的修法 |
|---|---|---|
| 人物一开口就把动机和主题讲清 | 台词是否符合当下目的、关系与知情范围 | 所有人都改成含糊和沉默 |
| 动作之后再解释一次情绪与意义 | 解释是否带来新信息，或具有必要的声音与节奏作用 | 一律删除心理描写 |
| 细节很多，场景仍然空 | 细节与人物注意、行动、处境是否有关 | 每个物件都变成伏笔 |
| 叙述提前揭穿人物尚不知道的事 | 视角约定与信息来源是否一致 | 强制所有作品只用限知视角 |
| 不同人物说话像同一位讲解员 | 各自想得到什么、回避什么、如何判断对方 | 每人增加固定口头禅 |
| 情节很顺，人物却没有选择重量 | 行动的理由、阻力与后果是否成立 | 每场都增加冲突和反转 |
| 每段都收束、升华、做结 | 当前段落是否需要停顿、转场或保持未决 | 禁止总结句和抒情 |

先请读者指出具体位置及影响，允许“这里我喜欢、那里我不喜欢”并存。不要先给读者一张模型编的禁词表，再让评价围绕它转。

## 三、如何从原文产生规则

### 1. 按叙事功能取样

研究材料可覆盖日常交涉、调查获取信息、危险判断、关系推进、场景收尾等。每类先找少量完整片段，足以看清前因后果再扩样；不要只挑名场面或摘警句。

保留章节、人物阶段、前置已知信息和片段结束后的变化。第一部与其他作品、二创叠加材料分开标记。当前本地同步包不包含小说原文，本轮不填入凭印象拟定的章节与引文。

### 2. 观察处理方式及其条件

每个片段回答：人物要什么？读者与人物各知道什么？哪些东西被写出，哪些延后？解释承担什么工作？这一处理在什么条件下会失效？

观察结果写成：原文位置 → 可见处理 → 可能作用 → 竞争解释 → 适用条件 → 候选决策。

“可能作用”保留推测标记。例如，一处省略可能源于前文已交代，而不代表作者普遍反对解释。应主动找原文中相反但同样有效的处理，防止把单段写法推广为通则。

### 3. 把规则写成有条件的决策

可采用的规则卡结构：

- 触发情境：什么情况下值得检查。
- 阅读问题：读者具体被什么打断。
- 候选动作：写作者可以怎样处理。
- 保留条件：什么情况下原写法更合适。
- 证据与状态：来自原文、用户改稿还是模型假说；是否验证。
- 可能副作用：怎样会被过度执行。

例如，“信息已经由动作充分传达，后续解释又未新增内容时，检查是否冗余；若解释承担误读、讽刺或人物自我辩护，则可能需要保留”。这是一条研究候选，不是本轮从原文提炼出的已证实规则。

## 四、用竞争假说定位问题

同一种出戏感可能有不同来源：

| 假说 | 后续怎样区分 | 若获得支持，优先改哪里 |
|---|---|---|
| 资料缺失或阶段错用 | 保持写作指令相同，只补必要事实 | 资料与场景装配 |
| 有资料但没有转成情境约束 | 事实相同，明确此刻目的、知情与关系边界 | 写作准备方法 |
| 叙事安排或语言选择不合适 | 同一资料条件下，加入少量候选规则 | 写作 skill |
| 模型没有采用或无法稳定执行规则 | 查看输出行为，并在后续不同任务重复观察 | 指令、模型或任务拆分 |
| 原有问题减轻，但规则造成新僵化 | 同时检查自然度、人物和可读性 | 收窄或删除规则 |

“给过资料”不等于模型采用了资料；“人物不像”也不能全部归为句子有 AI 味。证据不足时保留多种解释。

## 五、将来怎样检验，现在只确定实验设计

建议先做同一资料、同一任务下的 A/B：A 为现有写作指令，B 只增加一小组候选规则。其他条件尽量一致，记录实际模型、配置、上下文与 skill 版本。模型有随机性，单对结果只用于发现问题。

若怀疑收益来自示例，再单独比较“规则”“示例”“规则＋示例”，不在第一轮同时更改资料、模型和整套流程。若怀疑修订环节有效，应让两组拥有可比的修订机会，记录额外成本。

评价时隐藏方案身份、打乱顺序，评者先看任务和稿件，再揭盲。分别记录：

- 自然度与阅读意愿：哪里出戏、哪里愿意继续读。
- 人物、事实与因果：改善语言是否损害了这些方面。
- 人工修改负担：修改用时，以及必须重写的段落和原因；单纯修改字数不能代表负担。
- 规则引发的副作用：过度省略、故作隐晦、人物集体寡言等。

保持训练用片段与后续验证任务分开。若目标包含迁移到原创，再安排脱离诡秘专名的任务；同人有效不代表原创也有效。本轮不执行上述实验，不产生效果数字。

不以 AI 检测器分数作为本项目的成功标准。项目关心读者体验与返工，应直接评价这些目标。语言统计可用于定位重复现象，不宜变成强制配额。

## 六、何时值得固化为 skill

先用一页候选指令验证决策价值。经不同场景使用后仍有帮助的内容，再进入正式 skill；单次纠错保留在案例记录中即可。

初始结构可很小：

```text
fiction-scene-writing/
  SKILL.md
  references/
    guimi-anchor.md
```

这里只是结构建议，本轮没有创建这些文件。SKILL.md 放任务识别、场景准备、少量有条件的写作决策及必要复查；guimi-anchor.md 放已核对的锚点观察和适用范围。世界书、人物书继续由原资料系统维护，避免复制成另一套权威源。

写作前的准备可以很轻：此场景要发生什么变化、人物此刻知道什么和要什么、采用何种视角、有哪些相关约束。它为正文服务，不要求把分析表交给读者，也不强迫每场都有反转或关系变化。

候选规则若长期没有收益、增加修改负担或只能靠贴近例文才成立，应收窄、退回参考或删除。不得以“skill 已安装”“规则都遵守”替代成稿效果。

## 七、给 agent-workflow 的参考流程

目标与偏好校准 → 查阅原文和既有失败 → 提出多种解释 → 选最小候选干预 → 设计可比较的验证 → 根据阅读和改稿证据取舍 → 只固化反复有用的部分。

这条流程可对应现有 workflow 的探索、设计检查、实施、复审、修补与收尾，但写作质量需要读者判断，不能沿用代码测试全绿的完成口径。

后续如果采用协作者，观察原文、提出候选、评价稿件是不同工作；评价者尽量不先读“B 应该更好”的论证，避免把方案理由当成稿件证据。是否增加独立协作者，按具体争议和成本决定，本轮未启动协作者或外部模型调用。

每轮最小记录：本轮假说、使用材料、实际改动、观察结果、未决解释、下一步取舍。无效结果保留；新问题先判断是否影响本轮目标，避免审查自动扩成无限返工。
