## 方向

全局 `character_rules.json` 只保留跨书通用的切章、姓名、外貌等规则。一本书的体系用语（途径、序列、魔药，或另一本书里的功法、境界、组织职衔）来自**该书设定书**，编译成按书词表后再抽取。不把某书的能力名写进 atlas 核心规则。

已批但未落地的空位正好接这个：book profile 里的 `system_profile`、`lexicon_ref`（见 `草案/2026-11-06/04-book-profile配置接口.md` 第 5 节）。本草案是把它从「设计方向」收成前置步骤，不是另起一套接口。

## 推荐顺序

1. **设定书**：该书的力量体系、等级／序列名、组织与身份职务、稳定术语。空位保持待补，不发明。每条能追溯到设定书位置；外源或网补必须带标记。
2. **编译按书词表**：从设定书抽出机器可用的词表（能力／身份／组织等），记下设定书路径与 sha。人维护设定书，不在代码里手写一份平行名单。
3. **atlas**：按书叠加这份词表做抽取。无设定书、或神秘侧仍为 `unset` 时，不启用书专名词表；沿用已批语义（可抽可落盘，阻断第二段建卡）。
4. **prompt-os**：提示包里用到体系术语时，同时标明设定书条目和原文证据；不得把设定书没有的等级名写进待审卡。
5. **人审待审卡**。
6. **最后才润色角色卡**。润色不代替抽取，也不回写未确认内容。

在第 1–2 步对至少一本书接通并试跑之前，不宣称「链路前置做完」。

## 设定书至少要能提供

- 力量体系的通用说法（如魔药、序列、途径；或该书等价物）。
- 具体等级／职阶／组织名，供能力、身份分类，而不是事后按角色补词。
- 稳定术语，避免把牌面、称呼、日常技艺误当成体系事实。
- 版本可复现：run 的快照写入设定书 sha 与词表 sha，旧 run 不按「今天的设定书」重放。
