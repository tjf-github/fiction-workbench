## 4. 建议 JSON 形状（未冻死每一个键）

```json
{
  "lexicon_id": "gmzz-first-book",
  "book_id": "gmzz",
  "book_name": "诡秘之主",
  "usage": "first_book_extract",
  "system_profile": "gmzz-pathways",
  "sources": [
    {
      "role": "canonical",
      "path": "/workspace/诡秘之主-世界观设定梳理.md",
      "sha256": "<编译时读取的文件哈希>"
    }
  ],
  "compiled_at": "<Asia/Shanghai 时间>",
  "terms": [
    {
      "surface": "心理医生",
      "aliases": ["精神分析师"],
      "kind": "sequence_title",
      "field_hint": "能力",
      "pathway": "空想家",
      "sequence": 7,
      "source_section": "5.2",
      "origin": "first_book",
      "status": "confirmed"
    }
  ]
}
```

- `kind` 建议枚举：`sequence_title`｜`pathway`｜`system_term`｜`organization`｜`deity`｜`rank`。
- `status`：`confirmed` 才用于抽取分类；`unverified` 可留作查阅，不驱动 atlas。
- `origin`：`first_book`｜`guimi`｜`web_supplement`。第一部抽取只用 `origin=first_book` 且 `status=confirmed`。
- 词表文件自身也打 sha；run 快照同时写入设定书 sha 与词表 sha。旧 run 不按「今天的设定书／词表」重放。

本草案写就时，正本 sha256 为 `88e7d8a8a0a319312a2b3b1367b8dd42c29af39fbd57952347ad6fca883d51e8`，归来世界书为 `64630977ec8dfeedcfc03ad910c52496cc0b66bbc0ed0f594b6cb3db0f9a4395`。这只是起草时的快照，编译以当时文件为准。

## 5. atlas／prompt-os 怎么用（规格，尚未实现）

- 词表是 book profile 的叠加层，**不**写入全局 `character_rules.json`。
- 归属过滤仍先做：词面命中不等于该角色的能力或身份事实。
- 一句里既有序列称号、又有「小姐」这类身份通用词时，序列称号把该句导向**能力**，不再只因「小姐」进身份。这是奥黛丽后段晋升进错字段的对应改法，依据是设定书，不是代码里写死这些称号。
- 无 `lexicon_ref`、或神秘侧仍为 `unset`：不启用书专名词表；`unset` 仍可抽可落盘，阻断第二段建卡。
- prompt-os 引用体系术语时，同时标明设定书条目和原文证据；叠加词表里的网补名必须带原标记，不得写成第一部已坐实。
